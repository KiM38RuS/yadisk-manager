## 🐞 Открытые баги

### 🔴 Критично / часто встречается

- **WinError 5 при удалении папки** — «Не удалось удалить YaDiskManager: [WinError 5] Отказано в доступе: 'D:/YandexDiskTestFolder\Sync/YaDiskManager'». Возможно, папка открыта в Проводнике или другом приложении. Разобраться и предложить решение. *(см. Планы 2.2, 2.3)*
- **Окно зависает при многих действиях** — некоторые операции блокируют UI на несколько секунд. Найти все процессы, которые блокируют окно, вывести отчёт. *(= Планы 2.2)*
- **Стартовая загрузка > 4 минут** — AllFilesThread с resume offset=68000 тянет все файлы из облака через API, блокируя UI. Нужно: асинхронно, без блокировки, с прогрессом. *(= Планы 2.1)*
- **Выгрузка всех локальных файлов в облако при повторном запуске** — stale/changed/new детектор срабатывает некорректно? *(= Планы 2.3)*

### 🟡 Средний приоритет

- **Нет индикации удаления** — после инициирования удаления файла/папки нет никакой индикации. Ожидание: удаляемым элементам (и их родителям/детям) присваивается статус «синхронизация», затем удаление из интерфейса после подтверждения из облака и обновление статусов родителей.
- **Скачивание пустой папки** — ошибка «Выделите файлы или папки для скачивания или удаления локальной копии». При этом папка, в которой есть одна пустая подпапка и все файлы скачаны, помечается как «на компьютере».
- **«Оставить только в облаке» / «Сохранить на компьютере» с выделением файлов и папок** — действие применяется только к папкам, но не к файлам.
- **Выгрузка начинается до завершения полной загрузки данных из облака** — вопрос: это нормально? (возможно, стоит дожидаться завершения).
- **История поиска: показывается не всегда** — при некоторых условиях при нажатии на панель поиска показывается 1–2 последних запроса вместо пяти; последние результаты не показываются, когда фокус на панели поиска и в неё ничего не введено (например, выделить весь текст и удалить, или нажать крестик).
- **Контекстное меню строки поиска англоязычное** — Undo, Redo, Cut, Copy и т.д.; нужно русскоязычное.
- **Быстрая навигация по Дереву папок** — содержимое панели загружается быстро при навигации; можно ли сделать такую же быструю навигацию по дереву? *(идея/вопрос)*

### 🔵 Низкий приоритет

- **Ctrl+A выделяет «..»** — ломает логику кнопок «Сохранить»/«Оставить». *(= Планы 2.5)*
- **Разделители колонок** — столбец «Размер» заблокирован; последний столбец без правой границы. *(= Планы 2.12)*
- **Watchdog не видит новые файлы, созданные вне Менеджера** — при создании в Проводнике файл не появляется в таблице. *(= Планы 3.5)*
- **Авто-загрузка изменённого файла в облако** — есть через `_pend_upload`, но не сразу (2s debounce + flush). *(= Планы 3.6)*

### Исправленные баги (история)

⚠ **Исправлено (v0.11.10):**
- Выход из поиска (Esc) оставлял фильтр proxy-модели: после запроса «т» панель содержимого показывала лишь 9 папок корня из 28 (репорт «Как в коде предусмотрен выход из поиска» — остаток: Esc возвращал папку, но фильтр не сбрасывался). Фикс: `set_search_text("")` в ветке выхода из поиска.
- Статус-бар раздувался до 51 px из-за sizeHint брайль-спиннера (QStatusBar учитывает скрытые виджеты) → 22 px: WaveSpinner (QLabel + QTimer, кадры ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏).
- «Загрузка файлов...» навсегда висела слева и перекрывала статусы перезагрузки/выключения → индикатор загрузки перенесён в правую зону статус-бара.
- «Показать лог»/«Загрузка...» сдвигались при появлении прогресс-бара → слот фиксированной ширины 200 px.
- Долгие операции (поиск, удаление, вставка, DnD, синхронизация) не имели индикации → брайль-спиннер перед текстом в левой зоне (`_show_left_busy`/`_hide_left_busy`).
- Окно лога всегда висело поверх главного: `LogWindow` создавался с Qt-родителем (`Qt.Dialog`) → на Windows это Win32 owned-окно (owner = главное окно), которое физически не может уйти под владельца. Фикс: окно создаётся без Qt-родителя (ссылка на MainWindow — отдельно, через `self._main`). **Итоговое поведение (v0.11.10):** окно лога — спутник Менеджера: `Qt.Tool` без родителя (нет значка в таскбаре и в Alt+Tab), при активации Менеджера поднимается сразу за ним (`MainWindow._sync_log_zorder`), при сворачивании Менеджера прячется и восстанавливается вместе с ним; клик по логу поднимает его над Менеджером (не «всегда поверх»).
- ПКМ сбрасывал множественное выделение: обработчик контекстного меню таблицы/дерева безусловно делал `ClearAndSelect` по элементу под курсором → меню строилось для одного файла. Фикс: `ClearAndSelect` только если элемент под курсором НЕ в выделении (стандарт Windows). Для мультивыделения — общее меню `_build_multi_context_menu` (как в Проводнике): Сохранить на компьютере / Оставить только в облаке / Вырезать / Копировать / Вставить / Удалить; single-операции (Открыть, ссылка, переименовать, ZIP…) — только для одного элемента. Одно и то же меню для файлов, папок и смешанного набора. Счётчик «Выбрано: N» перенесён в статус-бар (`_status_selection_label`, `_update_selection_counter`): виден, пока выделено ≥2 элементов, со склонением.
- Внутренний DnD облачных путей не показывал drop-индикатор и не срабатывал: eventFilter возвращал `True` для DragEnter/DragMove, не давая view нарисовать индикатор; drop на папку в таблице давал target = текущая папка (no-op). Фикс: `canDropMimeData()`/`supportedDropActions()` в `FileTableModel` и `FolderTreeModel` (view принимает и рисует индикатор), для внутреннего mime DragEnter/DragMove → `return False` (view сам обрабатывает), drop на строку-папку в таблице нацеливается на неё. Новое: RMB-drag с меню «Копировать / Переместить» после отпускания (`_finish_drag`, `_pending_internal_drop`); LMB — копирование, +Shift — перемещение.
- Окно лога пропадало и блокировалось при открытии «Настроек» и подобных модальных окон (авторизация, обновление, подтверждения): (1) `exec()` даёт ApplicationModal → на Windows Qt деактивирует ВСЕ окна приложения (`EnableWindow(FALSE)`), включая лог. Фикс: `Qt.WindowModal` для SettingsDialog, AuthDialog (оба вызова), UpdateDialog (`setModal(True)` → `setWindowModality(Qt.WindowModal)`) и всех инстансных QMessageBox с parent — блокируется только окно Менеджера. Проверено эмпирически: Win32 `IsWindowEnabled` — при ApplicationModal лог деактивирован, при WindowModal остаётся активным и клик доходит.
- Окно лога не показывалось при старте (галочка «показывать при запуске» стоит) и пропадало при переключении на другое окно. Причины: (1) стартовый авто-показ вызывал `_sync_log_zorder()` до `window.show()` — Менеджер ещё не активен, ветка деактивации делала `lw.lower()` сразу после `setVisible(True)`, лог уходил на дно z-order; (2) при потере фокуса `lw.lower()` уводил лог под окно Менеджера. Фикс: старт — просто `setVisible(True)` без z-order-манипуляций (Менеджер, показанный позже, ложится поверх; в `--silent` лог не показывается); `_sync_log_zorder` больше не опускает лог при деактивации — только поднимает за Менеджером при его активации, прячет вместе со сворачиванием (`_on_manager_state_change`). Проверено: 9 сценариев (старт, чужое окно, модальный, активация, скрытый лог, минимизация/восстановление) — ALL_CHECKS_PASSED.
- FREEZE при выделении/навигации из-за N+1 SQL-запросов к БД со 100К+ файлов: `get_folder_aggregate_status()` вызывалась по одному разу на каждую папку под локом `self._lock`, блокируя UI-поток пока `AllFilesThread` пишет данные (до 5.8 с). Фикс: read-only соединение `_read_conn` (второе `sqlite3.Connection` к той же БД с WAL) — все SELECT на главном потоке идут через него; batch-запросы `get_folder_batch_aggregate_status()`, `file_exists_batch()`, `get_files_batch()` вместо поштучных вызовов; `_prefetch_sibling_statuses()` в дереве для batch-загрузки статусов соседних узлов.
- Счётчик «Выбрано: N» не сбрасывался при клике на пустое место таблицы/дерева: `eventFilter` вызывал `_update_toolbar_buttons()`, но забывал вызвать `_update_selection_counter()`. Фикс: добавлен вызов `_update_selection_counter()` в обе ветки (пустое место в таблице + пустое место в дереве).
