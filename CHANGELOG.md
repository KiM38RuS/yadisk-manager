# Changelog

## v0.11.11 (2026-08-28)

- **Новое**: навигация в стиле Проводника — адресная строка и кликабельные сегменты пути:
  - Адресная строка на втором тулбаре: ввод/вставка пути с переходом (Enter), история-комплитер, фокус по Ctrl+L / Alt+D; некорректный путь — откат к текущей папке, файловые пути отклоняются
  - `ui_breadcrumbs.py` — BreadcrumbBar: кликабельные сегменты пути, переполнение в выпадающее меню, режим редактирования по двойному клику; свежая ширина при ресайзе, отмена правки при программном set_path
  - `ui_shared.normalize_cloud_path` — нормализация ручного ввода (`disk:` префикс, обратные слэши, лишние слэши)
- **Новое**: мгновенное дерево из БД (DB-first) — раскрытие папок больше не ждёт API:
  - `db.get_dir_tree_levels` + `db.get_all_dir_paths` — уровни дерева и все пути одним запросом
  - `DbChildrenThread`/`DirPathsThread` — дети и пути читаются из БД в фоне
  - `_sync_tree_to_path` — синхронный ходок: дерево приводится к целевому пути из БД мгновенно, затем API-ответ мерджится (`merge_children_from_api`); generation-токен игнорирует устаревшие колбэки
  - Стрелки статусов при DB-first заполнении точь-в-точь как в БД; после мерджа статусы сохранённых и новых детей актуальны
  - При подъёме на уровень выше подсвечивается папка, из которой ушли (`select_after`)
- **Исправлено**: deadlock на пустых папках — вложенный захват лока в `is_folder_fully_synced` убран
- **Исправлено**: SQL-инъекция через LIKE-маски в `get_dir_tree_levels` — `%`/`_`/`\` в именах папок экранируются, стабильная сортировка уровней
- **Новое**: Net Heal — автообход DNS/TCP-блокировок Яндекс.Диска без админ-прав и без изменения системных настроек (`net_heal.py`, чистая логика без Qt):
  - Классификатор сетевых ошибок (DNS vs TCP), потокобезопасная очередь событий блокировок для UI
  - TTL-кэш IP с отрицательным кэшированием (плохой IP выбрасывается до конца TTL)
  - DoH-резолвер JSON-диалекта по голым IP (1.1.1.1 → 8.8.8.8, таймаут 5с); malformed-ответ = отказ эндпоинта
  - HealedAdapter монтируется на сессию YaDiskAPI только при включённом обходе: системный DNS всегда первый, при сбое соединение открывается на IP из кэша/DoH, но TLS SNI и проверка сертификата остаются на исходном хосте
  - Разовый диалог «Включить обход?» при первой блокировке (выбор помнится в конфиге), нейтральная подсказка про VPN — одна за сессию, если обход не помог; события разбираются существующим 100-мс таймером очереди результатов
  - Чекбокс «Обход DNS-блокировок (DoH)» в настройках; переключение действует сразу, без перезапуска
- **Исправлено (критическое)**: авто-проверка обновлений падала с `AttributeError: 'MainWindow' object has no attribute '_update_download'` — в `_init_updates()` не инициализировался атрибут `_update_download` (добавлен `self._update_download = None`), из-за чего `_check_updates_auto`/`_check_updates_manual` падали через ~20 с после старта и при каждой периодической проверке, а авто-обновление не работало. Теперь проверка доходит до реального запроса к GitHub
- **Изменено**: галочка «Обновляться до бета-версий» включена по умолчанию (`db.get_update_beta_enabled()` → `True`) — все релизы выходят как pre-release, и без неё апдейтер (через `/releases/latest`) не видит обновлений совсем

- **Исправлено**: внутренний drag-and-drop облачных файлов/папок не показывал drop-индикатор на папке-назначении и не срабатывал при отпускании — eventFilter съедал DragEnter/DragMove (`return True`), не давая QTreeView/QTableView нарисовать индикатор, а drop на папку в таблице нацеливался на текущую папку («само в себя» → no-op). Теперь: `canDropMimeData()`/`supportedDropActions()` в моделях (`FileTableModel`, `FolderTreeModel`) — view принимает и рисует индикатор; drop на строку-папку в таблице нацеливается на неё (как в Проводнике)
- **Новое**: drag-and-drop правой кнопкой мыши — после отпускания показывается меню «Копировать / Переместить» (Esc или клик мимо — отмена); LMB: копирование, +Shift — перемещение. Работает для таблицы и дерева (`_finish_drag`, `_pending_internal_drop`)
- **Изменено**: окно лога снова спутник Менеджера — флаг `Qt.Tool` без Qt-родителя: нет значка на панели задач и в списке Alt+Tab; при активации Менеджера (Alt+Tab, клик по значку, клик по окну) лог поднимается на передний план сразу за ним (`_sync_log_zorder`), при сворачивании Менеджера прячется и восстанавливается вместе с ним (`_on_manager_state_change`); клик по логу по-прежнему поднимает его над Менеджером — «всегда поверх» больше нет
- **Исправлено**: при открытии окна «Настройки» (и подобных: авторизация, обновление, подтверждения) окно лога пропадало и блокировалось до закрытия диалога. Две причины: (1) `dlg.exec()` превращает диалог в ApplicationModal — на Windows Qt вызывает `EnableWindow(FALSE)` для ВСЕХ окон приложения, включая лог; (2) `_sync_log_zorder` при деактивации Менеджера опускал лог под главное окно. Теперь: Настройки/AuthDialog/UpdateDialog/QMessageBox с parent используют `Qt.WindowModal` — блокируется только окно Менеджера, безродительский лог-спутник остаётся видимым и интерактивным
- **Исправлено**: окно лога не показывалось при старте, несмотря на галочку «показывать при запуске», и пропадало при переключении на другое окно. Причины: (1) стартовый авто-показ вызывал `_sync_log_zorder()` ДО `window.show()` (main.py) — Менеджер ещё не активен, и ветка деактивации делала `lw.lower()`, уводя лог на дно z-order сразу после показа; (2) при потере фокуса Менеджером `lw.lower()` прятал лог под окно Менеджера. Теперь: старт просто показывает лог (Менеджер, показанный позже, ложится поверх; silent-режим `--silent` лог не показывает), а `_sync_log_zorder` больше не опускает лог при деактивации — он прячется только вместе со сворачиванием Менеджера, поднимается сразу за ним при активации
- **Исправлено (производительность)**: FREEZE при выделении/навигации из-за N+1 SQL-запросов к БД со 100К+ файлов — `get_folder_aggregate_status()` вызывалась по одному разу на каждую папку под локом `self._lock`, блокируя UI-поток пока `AllFilesThread` пишет данные. Масштабные оптимизации:
  - Добавлено read-only соединение `_read_conn` (второе `sqlite3.Connection` к той же БД с WAL) — все SELECT-запросы на главном потоке идут через него, не блокируясь на `self._lock` с фоновыми потоками
  - `refresh_statuses()` в таблице: вместо N вызовов `get_folder_aggregate_status()` — один `get_folder_batch_aggregate_status()` через UNION ALL с range-запросами
  - `_collect_selection_statuses()`: аналогичный batch-запрос вместо поштучных вызовов
  - `_on_poll_result()`: `file_exists_batch()` + `get_files_batch()` вместо 100+ индивидуальных запросов в цикле
  - `_prefetch_sibling_statuses()` в дереве: batch-загрузка статусов всех незагруженных соседних узлов за один запрос
