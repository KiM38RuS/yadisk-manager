# Локализация лога — как это работает и как добавить свой язык

> Документация для разработчика / переводчика. Пользовательская документация
> находится в CHANGELOG.md.

## TL;DR

Лог YaDisk Manager теперь **переводится на русский язык автоматически**.
Вся логика — в одном файле `l10n.py`. Чтобы добавить другой язык, нужно
добавить один словарь и одну строку кода — **переписывать вызовы `logger.*`
в десятках файлов не нужно**.

## Как это устроено

1. В коде сообщения пишутся по-английски (так проще отлаживать и не зависит
   от данных): `logger.info("Downloaded %s (%d bytes)", name, size)`.
2. `l10n.LOG_RU` — словарь «английский шаблон → русский перевод»:
   ```python
   "Downloaded %s (%d bytes)": "Скачано %s (%d байт)",
   ```
3. `LogTranslatingFormatter` (наследник `logging.Formatter`) **до** подстановки
   аргументов заменяет шаблон сообщения на перевод. Аргументы (`name`, `size`)
   подставляются уже в переведённый шаблон, поэтому плейсхолдеры `%s`, `%d`,
   `%r`, `%(name)s` и т.п. должны **сохраняться в переводе как есть**.
4. Этот форматтер используется везде, где лог пишется:
   - консоль + файл `%APPDATA%\yadisk-client\yadisk.log` → `main.py`;
   - окно лога (GUI) → `ui_log.py` (`LogHandler`);
   - так что окно лога и файл лога выглядят одинаково.

## Управление языком

Язык берётся из конфига `log_lang` (по умолчанию `"ru"`):

- `db.get_log_language()` / `db.set_log_language("en")` — API в `db.py`;
- `l10n.set_language("en")` — установить язык напрямую (для тестов/скриптов);
- `l10n.get_language()` — текущий язык;
- `l10n.translate("...")` — перевести одну строку.

`"en"` — это «выключить перевод»: английские шаблоны выводятся как есть.
Любой незнакомый шаблон (в т.ч. будущие новые сообщения) выводится на языке
оригинала — перевод никогда не «ломает» лог.

## Как добавить язык (пошагово)

Допустим, хотим добавить немецкий (`de`):

1. Откройте `l10n.py`, скопируйте словарь `LOG_RU` целиком.
2. Переведите **значения** на немецкий. **Ключи не трогайте** — это исходные
   английские шаблоны из кода, по ним идёт поиск.
3. Сохраните все плейсхолдеры в переводе: `%s`, `%d`, `%r`, `%.1f`,
   `%(name)s` и т.д. Проверку делает `l10n.verify()`.
4. Добавьте словарь в реестр:
   ```python
   LOG_DE = { ... }  # ваш перевод
   TRANSLATIONS = {
       "ru": LOG_RU,
       "de": LOG_DE,
   }
   ```
5. Всё. Переключение: `db.set_log_language("de")` или `l10n.set_language("de")`.

## Как найти новые сообщения (после правок кода)

После добавления/изменения английских `logger.*`-сообщений:

```bash
cd D:\Program_files\YaDiskManager
python -c "import l10n; print(l10n.verify())"
```

`verify()` вернёт список ошибок «несовпадение плейсхолдеров». Покрытие словаря
можно проверить так (ищет все `logger.xxx("...")` в корневых `*.py`):

```bash
python - <<'PY'
import re, glob, l10n
msgs = set()
for f in glob.glob("*.py"):
    src = open(f, encoding="utf-8").read()
    msgs |= set(re.findall(r'logger\.\w+\(\s*(["\'])(.*?)\1', src, re.S))
missing = sorted(m for m in msgs if not m[1] or not any('\u0400' <= c <= '\u04FF' for c in m[1]))
print("Не переведено:", len([m for m in msgs if m[0] == m[1]]))
PY
```

> Утилита `_check_l10n.py` в корне проекта (временная) делает ровно эту
> проверку — можно удалить, если не нужна.

## Правила перевода

1. **Плейсхолдеры сохраняются** — это главное правило, нарушение ломает лог
   (`TypeError: not enough arguments for format string`).
2. Не переводите имена потоков/классов: `AllFilesThread:`, `DLW:`,
   `ApiListThread:` — по ним ищут в коде при разборе лога. Переводите смысловую
   часть после двоеточия.
3. Не переводите имена файлов, `cloud_only`, `complete_pending_op`,
   `config.json` и т.п. — это идентификаторы.
4. `→`, `—`, эмодзи (`⚠️`, `📋`, `🔄`, `🗑️`, `✅`) — не стирайте: они несут
   смысл и используются для раскраски (`ui_log._level_color`).
5. `%s` и `%d` можно менять местами в русском предложении, но **не меняйте
   их порядок между собой** — аргументы подставляются по позиции.

## Что НЕ переводится (намеренно)

- `IPC: ping` — технический зонд, спам в лог при каждом `--restart`.
- Сообщения Qt (`Qt warning`, `Qt critical` и т.д.) — они приходят из C++
  напрямую в stderr, минуя `logging` (см. `main._qt_message_handler`).
- Трейсбеки исключений (`logging.critical` из `_log_excepthook`) — это
  технический дамп для разработчика, переводить их бессмысленно.

## Куда ведёт локализация интерфейса

Интерфейс приложения сейчас **уже полностью на русском** (жёстко зашит в коде,
см. `UI_LOCALIZATION.md`). Эта система переводит только **лог**. Для перевода
всего интерфейса на другой язык нужна отдельная работа — оценка в
`UI_LOCALIZATION.md`.
