## 2. Threading lock в Database

**Описание бага (б):** `set_downloaded()` и `upsert_files_batch()` могли конфликтовать, вызывая `cannot start a transaction within a transaction`.

### Тест 2.1 — параллельные операции

| | |
|---|---|
| **Условия** | 20+ скачанных файлов в разных папках |
| **Шаги** | 1. Выделить папку с 10 файлами → «Оставить только в облаке»<br>2. Сразу (не дожидаясь) выделить другую папку → «Сохранить на компьютере» |
| **Ожидание** | Все операции завершаются без ошибок. В логе нет `"sqlite3.DatabaseError"`, `"cannot start a transaction"`, `"database is locked"` |
| **Провал** | Любой DatabaseError в логе |

### Тест 2.2 — навигация во время записи

| | |
|---|---|
| **Условия** | Много файлов |
| **Шаги** | 1. Запустить «Оставить только в облаке» для 15+ файлов<br>2. Во время операции активно переключать папки в дереве |
| **Ожидание** | Нет DatabaseError. UI не зависает (навигация работает) |
| **Провал** | Ошибка БД или зависание |

## 3. remove_file под lock

**Описание бага (в):** `remove_file` мог не синхронизироваться с транзакциями `upsert_files_batch`.

### Тест 3.1 — массовое удаление + upsert

| | |
|---|---|
| **Условия** | Файлы загружены в БД |
| **Шаги** | 1. Выделить 10+ файлов → «Оставить только в облаке» (вызовет `remove_file` для перезаписи? Нет, `set_cloud_only`) — на самом деле `remove_file` вызывается в `_handle_file_moved`.<br>2. Лучше: переименовать 5+ файлов в кеше (вызовет `moved` → `remove_file` + `upsert_file`) |
| **Ожидание** | Ни одной DatabaseError в логе |
| **Провал** | Ошибка БД |

## 9. Проверка нового фикса: пропуск загрузки уже синхронизированных файлов

**Новый фикс (v0.10.2):** `_on_meta_fetched` теперь проверяет `cloud_md5 == local_md5` перед загрузкой.

### Тест 9.1 — файл уже в облаке (самый важный)

| | |
|---|---|
| **Условия** | Есть файл, скачанный на ПК и загруженный в облако (статус downloaded, с `last_sync_md5`) |
| **Шаги** | 1. Убедиться, что файл НЕ менялся локально<br>2. Спровоцировать попадание файла в `_pend_upload`: закомментировать проверку в StartupScanThread, или<br>   просто запустить «Сохранить на компьютере» для уже скачанного файла (вызовет `_start_download` → download, не upload)<br>3. Наблюдать лог |
| **Ожидание** | В логе: `"File already in sync, skipping upload: /путь/к/файлу"`. Файл НЕ загружается заново |
| **Провал** | Файл уходит на загрузку (`"_start_upload"`, `UploadWorker`) |

### Тест 9.2 — новый локальный файл (всё ещё загружается)

| | |
|---|---|
| **Условия** | Новый файл, созданный локально, которого нет в облаке |
| **Шаги** | 1. Создать файл в кеше (не через API Менеджера)<br>2. Дождаться watcher → created → `_pend_upload`<br>3. Наблюдать лог |
| **Ожидание** | Файл загружается в облако как обычно. Строки `"skipping upload"` нет |
| **Провал** | Файл не загружается |

### Тест 9.3 — изменённый локальный файл (загружается)

| | |
|---|---|
| **Условия** | Скачанный файл, изменённый локально |
| **Шаги** | 1. Отредактировать файл в кеше (Блокнотом)<br>2. Дождаться watcher → modified → `_pend_upload`<br>3. Наблюдать лог |
| **Ожидание** | `cloud_md5 ≠ local_md5` → файл загружается в облако (нормальная синхронизация) |
| **Провал** | Файл помечен `"skipping upload"` и не загружается |
