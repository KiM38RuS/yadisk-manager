## Архитектура вашего приложения
Чтобы программа работала стабильно, вам нужно разбить её на 4 изолированных модуля. Вы можете скармливать агенту каждый модуль по отдельности и гонять его по циклу Loop Engineering до идеала:

   1. Модуль OAuth-авторизации: Получение безопасного токена доступа (Access Token) через браузер, чтобы программа имела право заходить в ваш Диск.
   2. Модуль отслеживания изменений (File Watcher): Фоновый процесс Windows, который следит за вашей локальной папкой и мгновенно узнает, если вы добавили, удалили или переименовали файл.
   3. Модуль API-клиента: Набор функций, которые отправляют файлы на Яндекс Диск (запросы GET, PUT, DELETE к https://yandex.net).
   4. Очередь загрузок (Sync Queue): Логика, которая обрабатывает конфликты (например, если файл открыт в другой программе или пропал интернет).

Когда базовые запросы работают, переходите к самой сложной части — фоновой работе.

Промпт для Агента:

Запусти цикл Loop Engineering: найди критические проблемы (например, что делать, если файл еще пишется на диск, а программа уже пытается его загрузить?) и переписывай код, пока не решишь эти проблемы.»

## Главные «подводные камни» Яндекса, о которых нужно знать агенту
Когда вы запустите цикл улучшения кода, агент столкнется с ограничениями API Яндекса. Заранее добавьте эти правила в его контекст, чтобы сэкономить время:

* Двухэтапная загрузка: Яндекс Диск не принимает файлы напрямую. Сначала нужно отправить запрос GET на получение ссылки для загрузки, и только потом отправлять сам файл PUT-запросом на полученный URL [1].
* Лимиты на запросы (Rate Limits): Если загружать много мелких файлов слишком быстро, Яндекс заблокирует запросы (ошибка 429). Агенту необходимо внедрить алгоритм экспоненциальной задержки (Exponential Backoff).
* Большие файлы: Файлы больше 2 ГБ через обычный REST API загружать тяжело. Нужно просить агента реализовать кусковую (чанковую) загрузку, если планируете хранить фильмы или тяжелые архивы.
