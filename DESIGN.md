## 1. Введение и цели

### 1.1. Что это

Кроссплатформенный десктопный клиент для Яндекс.Диска, написанный на **Python + PySide6**. Основной сценарий — **on-demand синхронизация**: файлы видны в облаке, скачиваются по требованию (по двойному клику), изменения отслеживаются и автоматически загружаются обратно в облако.

### 1.2. Ключевые отличия от официального клиента

| | Официальный Яндекс Диск 3.0 | YaDisk Manager |
|---|---|---|
| **Стоимость** | Требуется подписка Яндекс 360 для скачивания/загрузки | **Бесплатно** — использует публичный REST API |
| **Синхронизация** | Автоматическая фоновая (Selective Sync) | On-demand + ручная (двойной клик → скачать) |
| **UI** | Нативное Win32 окно с деревом + таблицей | PySide6 (Qt), кроссплатформенный |
| **Скриншоты** | Встроенный редактор с горячими клавишами | ❌ Не реализовано |
| **Заметки** | Rich-text редактор, до 500 заметок | ❌ Не реализовано |
| **Dropzone** | Область поверх окон для drag&drop | ❌ Не реализовано |

### 1.3. Почему это вообще работает

Яндекс предоставляет публичный REST API (`cloud-api.yandex.net/v1/disk`) с методами для просмотра, скачивания, загрузки и управления файлами. Ограничения бесплатного аккаунта: 10 ГБ места (базовый), 50 ГБ (промо и т.д.). API не требует подписки.

### 3.4. Таблица файлов (справа)

| Колонка | Описание | Сортировка |
|---|---|---|
| **Имя** | Иконка эмодзи + имя файла/папки | По умолчанию ↑ (возрастание), папки первыми, «..» всегда на первом месте |
| **Размер** | Человекочитаемый (B/KB/MB/GB) | Числовая |
| **Изменён** | `dd.MM.yyyy HH:mm` | Первый клик ↓ (сначала новые), повторный клик переключает Asc↔Desc |

> **Сортировка:** Используется `QSortFilterProxyModel` с кастомным `lessThan()`.
> Проблема: `dynamicSortFilter=True` заставляет `sort()` работать через zero-timer
> (`_q_sort`), из-за чего таблица отрисовывается до фактической сортировки (фликер).
> Решение: отключать `dynamicSortFilter` перед `set_path()`, сортировать синхронно,
> включать обратно — см. `_sort_table_sync()`.
> 
> При сортировке папки всегда выше файлов, «..» — всегда первый.
> Дефолт: колонка 1 (Имя) Ascending. Колонка 3 (Изменён): первый клик → Descending.
>
> **ВАЖНО:** `RowHoverDelegate._paint_name_cell()` читал `src._items[index.row()]`,
> где `index` — ПРОКСИ-индекс (отсортированный), а `_items` индексируется по
> SOURCE-строкам (порядок из БД/API). После сортировки proxy row ≠ source row →
> делегат брал неправильный элемент, рисуя неверное имя для каждой строки.
> Фикс: `model.mapToSource(index)` перед обращением к `_items`.
> 
> В версии 0.6 этой проблемы не было, т.к. эмодзи были встроены в `DisplayRole`
> строкой `f"{icon} {item['name']}"`, и делегат не переопределял paint() для колонки имени.
| **Статус** | ☁️ в облаке / 💾 на компьютере / ✏️ изменён | downloaded → modified → cloud_only |

- `FileTableSortModel(QSortFilterProxyModel)` — фильтр по **имени** (колонка 1), регистронезависимый
- Приоритет сортировки: `..` всегда первый → папки (независимо от направления) → содержимое
- **Отображение имён файлов** — эмодзи-иконка + имя. Иконка рендерится как текст в кастомном делегате (`RowHoverDelegate._paint_name_cell`), не как `QPixmap` — это предотвращает обрезку по краям. Длинные имена обрезаются с многоточием **посимвольно** через `fontMetrics.elidedText()`. `wordWrap = False` — чтобы элизия не пыталась делить по словам.
- `sort(column 3, Ascending)` → первый раз сбрасывается в `Descending`. При повторном клике Qt сама переключает Asc↔Desc
- `ExtendedSelection` — множественное выделение
- `setSortingEnabled(True)` — по дефолту колонка 1 (Имя) ↑ Asc
- Двойной клик: скачать + открыть, или открыть папку
- Подсветка при наведении — через `RowHoverDelegate (QStyledItemDelegate)`: Highlight с `setAlpha(50)`
- Контекстное меню (правый клик): ✅ Сохранить на компьютере / ☁️ Оставить только в облаке (в зависимости от статуса выделения), 🔗 Скопировать ссылку, ✏️ Переименовать, 📂 Открыть в Проводнике (только если есть локально), 🌐 Просмотреть на сайте (открывает файл/папку на disk.yandex.ru), 🗑 Удалить. **ПКМ не снимает предыдущее выделение**, добавляет текущий элемент к выделению
- **Ширина столбцов**: статус=28px (Fixed, нельзя изменить ширину), имя=300px, размер=ResizeToContents, изменён=100px. Остальные — Interactive
- **Разделители заголовков**: `border-right: 1px solid palette(Midlight)`
- **Выделение через Ctrl+A** не включает «..»
- **Подсветка элементов в древе папок** — аналогичная подсветке в таблице (серый/прозрачно-синий фон)
- **Элемент `..`** — первая запись в таблице для перехода в родительскую папку; не участвует в определении кнопки-переключателя (не влияет на «Сохранить/Оставить»)

### 3.5. Синхронизация выделения между панелями

Выделение в дереве папок и таблице файлов — **взаимоисключающее**:

- При выделении **любого элемента в таблице** → выделение в дереве **снимается** (и наоборот)
- При **клике по пустому месту в любой панели** → выделение **снимается в обеих панелях** сразу
- Механизм: `_on_tree_selection_changed` и `_on_table_selection_changed` вызывают `clearSelection()` противоположной панели
- Защита от рекурсии: флаг `_selection_updating` блокирует повторный вход
- Клик по пустому месту обрабатывается в `eventFilter` (viewport) — чистит обе панели напрямую под `_selection_updating`, так как `clearSelection()` без текущего выделения не эмитит `selectionChanged`
- При навигации («..», Backspace, Enter по папке) — дерево чистится явно перед `_navigate_to_folder`

### 3.6. Режим крупных значков

В правой части окна (справа от прогресс-бара) находятся переключатели режима отображения:
- 📋 Таблица (текущий режим)
- 📦 Крупные значки (альтернативный режим)

В режиме крупных значков файлы и папки отображаются в виде сетки (QListView / QListWidget).
Статус файла отображается иконкой-оверлеем:
- ✅ Белая галочка в зелёном кружочке — сохранён на ПК
- ☁️ Белое облачко с синей обводкой — в облаке
- 🔄 Две белые круговые стрелки в синем кружочке — идёт синхронизация (возможна анимация)

### 3.7. Системный трей

- Иконка: `YD-NL-DT.ico` / `YD-NL-LT.ico` (авто-определение тёмной темы)
- Меню: Показать, Скрыть, Настройки, Выход
- **Одиночный клик ЛКМ** по иконке трея — открыть окно (если не в фокусе). Если окно уже в фокусе — ничего не делать.
- **Двойной клик** — игнорируется (ничего не происходит).
- **Контекстное меню трея**: состояние определяется флагом `_user_hidden`

  - Окно видимо → только «Скрыть»
  - Без фокус-зависимости (избегает ложного срабатывания при открытии меню)
- **Закрытие окна** (кнопка X) → сворачивается в трей (не завершает процесс). Все фоновые процессы (watcher, таймеры, скачивания) продолжают работу.
- **При первом сворачивании** — всплывающее уведомление от трея: «Окно свёрнуто в трей. Нажмите на значок программы, чтобы открыть его снова.»
- **Полное закрытие программы** — только через меню Файл > Выход (Ctrl+Q) или пункт Выход в контекстном меню трея.

### 3.8. Диалоги

- **AuthDialog** — инструкция по получению OAuth-токена + инлайн-верификация

### 3.9. Оформление и смена темы

Тема оформления реализована через **явные hex-цвета в QSS** (не через palette):

- `main.py` устанавливает `QStyleFactory.create('Fusion')` сразу после `QApplication()` — до создания любых виджетов
- `_apply_theme()` генерирует полный QSS для каждого виджета с hex-цветами (светлая `#000000`, тёмная `#FFFFFF`)
- После `app.setStyleSheet()` все виджеты проходят `unpolish/polish` — иначе Qt кеширует стили
- **Никаких `palette()` ссылок в QSS** — все цвета жёстко заданы hex-кодами
- `_apply_theme()` включает три палитры (светлая / тёмная / системная) и три набора QSS

**Цвета тёмной темы:** VS Code / Fluent Design (`#1E1E1E` фон, `#252526` surface, `#094771` highlight, `#007ACC` accent).

**Подсказки (ToolTip):**
- Принудительный QSS: `QToolTip { background-color; color; border }` — так как на Windows QPalette.ToolTipBase может игнорироваться
- Светлая тема: фон `#ffffe5`, текст `#000000`, рамка `#C0C0C0`
- Тёмная тема: фон `#383838`, текст `#CCCCCC`, рамка `#555555`

**Ховер кнопок в панели кнопок:**
- Полупрозрачный синий фон: `palette(Highlight)` с альфа-каналом (approx. 30% прозрачности)
- В светлой теме: светло-голубой оттенок
- В тёмной теме: синеватый оттенок, заметный на тёмном фоне

### 3.10. Клавиатурная навигация

| Клавиша | Действие | Когда |
|---------|----------|-------|
| **Enter** | Открыть выделенный файл/папку (как двойной клик) | Таблица активна |
| **Backspace** | Перейти в родительскую папку | Таблица активна, не корень |
| **F2** | Переименовать выделенный элемент | Таблица или дерево активны |
| **А-Я A-Z 0-9** | Type-ahead: выделить первый элемент, начинающийся с введённых символов; при повторном нажатии того же символа — следующий элемент | Таблица активна |
| **Ctrl+A** | Выделить все элементы, **кроме «..»** | Таблица активна |

- Буфер type-ahead сбрасывается через 500 мс бездействия

## 6. API-интеграция

### 6.1. REST-клиент (`disk_api.py`)

Базовый URL: `https://cloud-api.yandex.net/v1/disk`

| Метод API | HTTP | Параметры | Используется для |
|---|---|---|---|
| `GET /` | GET | — | Информация о диске |
| `GET /resources` | GET | path, limit, offset | Навигация по папкам |
| `GET /resources/files` | GET | limit, offset | Все файлы (flat) |
| `GET /resources/last-uploaded` | GET | limit | Polling изменений |
| `GET /resources/download` | GET | path | Получение ссылки на скачивание |
| `GET /resources/upload` | GET | path, overwrite | Получение ссылки на загрузку |
| `PUT /resources` | PUT | path | Создание папки |
| `DELETE /resources` | DELETE | path, permanently | Удаление |
| `PUT /resources/publish` | PUT | path | Публичная ссылка |
| `PUT /resources/unpublish` | PUT | path | Снять публичный доступ |
| `POST /resources/move` | POST | from, path, overwrite | Перемещение/переименование |
| `POST /resources/copy` | POST | from, path, overwrite | Копирование |

### 6.2. Ключевые особенности реализации

- **Rate limiter** (40 запросов/сек) — скользящее окно, предотвращает 429 Too Many Requests
- **Retry с exponential backoff** — для 429 и 503 ошибок
- **AuthError** — детекция 401, перезапрос токена через диалог
- **Нормализация путей** — убирает префикс `disk:`, гарантирует `/` в начале

### 6.3. Корзина и история

- **Корзина** — API поддерживает `DELETE /resources?path=...&permanently=false`. Файлы попадают в корзину Яндекс.Диска, доступную по `https://disk.yandex.ru/client/trash`. Просмотр корзины через REST API возможен (эндпоинт `/trash/resources`). YDM может добавить просмотр и очистку корзины.
- **История изменений** — API возвращает метаданные файла (версия `revision`), но нет публичного эндпоинта для списка изменений по одному файлу. Возможно только через `GET /resources?path=...&limit=1` с пагинацией по истории — требует дополнительного исследования.

## 7. Движок синхронизации

### 7.1. Фазы `full_sync()`

При старте программы (или по кнопке «Синхронизировать»):

```
Phase 1: GET /resources/files (все файлы из облака)
         → cloud_by_path / cloud_by_md5
Phase 2: os.walk(cache_dir)
         Для каждого локального файла:
           Если совпадает MD5 → matched
           Если локальный новее → upload
           Если облачный новее → download
           Если MD5 совпадает с другим путём → move (файл перемещён в облаке)
           Если был downloaded, но удалён из облака → delete локально
           Если новый локальный → upload new
Phase 3: Очистка БД от файлов, помеченных downloaded, но отсутствующих локально
```

### 7.2. Watchdog (`watcher.py`)

- Использует `watchdog.Observer` (рекурсивный мониторинг)
- **Debounce 3 секунды** — кумуляция изменений (чтобы не дёргаться на каждое автосохранение)
- Игнорирует временные файлы (`.filename`, `filename~`, `*.tmp`)
- При изменении → через 2 секунды проверка метаданных облака (разрешение конфликтов) → загрузка

### 7.3. Стратегия разрешения конфликтов

```
IF last_sync_md5 совпадает с cloud_md5:
    → Простая загрузка (без конфликта)
ELSE IF cloud_md5 != last_sync_md5:
    → Диалог: оставить локальный / скачать облачный / отмена
```

### 7.4. Авто-загрузка новых файлов в synced-папках

Если все файлы в папке имеют статус `downloaded`, папка считается «полностью скачанной».
При обнаружении нового файла в такой папке (через poll / после full_sync) файл автоматически скачивается.

Механизмы:
1. **Poll (каждые 60с)** — `_on_poll_result()` проверяет родительскую папку до добавления файла в БД
2. **After full_sync** — `_auto_download_orphans_in_synced_folders()` проверяет все cloud_only-файлы
