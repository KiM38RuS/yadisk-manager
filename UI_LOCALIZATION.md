# Локализация интерфейса — текущее состояние и оценка

> Документация для разработчика / переводчика. Дополняет `LOG_LOCALIZATION.md`
> (там — про перевод лога, эта страница — про весь интерфейс).

## Текущее состояние (факт)

**Интерфейс YaDisk Manager уже на 100% русский** и это **единственный язык**
программы. Русский текст зашит прямо в код — строки виджетов, меню, трея,
диалогов, статусов, контекстных меню лежат в `*.py` как литералы.

Оценочный масштаб (проверено скриптом по корневым `*.py`):

| Что | Сколько |
|---|---|
| Строк с кириллицей (все, включая docstring-и) | ~590 |
| Пользовательских строк интерфейса (оценка: виджеты, меню, сообщения, статусы) | ~250–300 |
| Файлов, где встречается текст интерфейса | ~15 (ui.py, ui_table_model.py, ui_dialogs.py, ui_shared.py, ui_threads.py, ui_breadcrumbs.py, ui_search_edit.py, main.py, db.py, sync.py, …) |
| Механизм локализации интерфейса | **отсутствует** |

В отличие от лога, где сообщения — это **шаблоны в одном потоке** (все идут
через `logging.Formatter`), строки интерфейса **разбросаны по коду** и
передаются напрямую в конструкторы Qt-виджетов:

```python
self._btn = QPushButton("Скачать", self)          # ui.py
label = QLabel("В облаке")                        # ui_table_model.py
reply = QMessageBox.question(self, "Выйти из аккаунта", "Вы уверены?")
```

## Ответ на вопрос «будет ли слишком большой работой»

**Документацию сделать — нет, это дёшево** (этот файл — и есть она).

**А вот сделать сам интерфейс локализуемым — да, это большая работа**, и вот
почему (оценка основана на реальном масштабе кода):

1. **Нет инфраструктуры i18n.** Нужно либо подключать Qt Linguist
   (`QTranslator` + `.ts`/`.qm`), либо делать свой `tr()`-механизм как для
   лога. Сейчас нет ни того, ни другого.

2. **~250–300 строк нужно вытащить из кода** в каталог переводов и заменить
   все вызовы `QPushButton("…")`, `QLabel("…")`, `QMessageBox(…)` на
   `tr("…")` / `_(…)`. Это правки в ~15 файлах, каждая строка — ручная.

3. **Русская морфология — самая сложная часть.** «1 файл / 2 файла / 5 файлов»,
   «элемент/элемента/элементов», падежи в сообщениях. Логу это простительно
   (там и так пишем «файлов: N»), а в интерфейсе пользователь заметит
   неправильные окончания сразу. Нужен plural-механизм.

4. **Регрессионный риск.** ui.py ~3.4K строк, ui_table_model.py ~2K. Массовая
   замена строк — почти гарантированные опечатки, сломанные переносы, потеря
   переменных в f-string. Потребуется ручная проверка всего GUI.

5. **Нет второго языка в продуктовой повестке.** Продукт нацелен на
   русскоязычного пользователя (так в AGENTS.md). Вкладывать неделю-две в
   i18n-фреймворк без реального запроса на второй язык — преждевременно.

**Итог: документация — сделана (см. ниже). Полная локализация интерфейса —
не рекомендуется сейчас**; это отдельная задача на ~1–2 недели, а не правка
на вечер. Когда появится реальная потребность (например, английская версия) —
возьмите план ниже.

## Как сделать интерфейс локализуемым (план, когда понадобится)

### Вариант A — Qt Linguist (рекомендуется для PySide6)

1. Подключить `QTranslator` в `main.py`, загружать `.qm` по языку.
2. Заменить пользовательские строки на `self.tr("…")` в виджетах и
   `QCoreApplication.translate("ctx", "…")` в не-QObject-коде.
3. Сгенерировать `.ts` (`pyside6-lupdate`), перевести, собрать `.qm`
   (`pyside6-lrelease`).
4. Плюс: штатные plural-формы Qt (`%n` + `tr("…", "", n)`), инструменты
   перевода, хот-релоад. Минус: `.ts` раздувается, требует инструментов.

### Вариант B — свой словарь (как в l10n.py)

1. В `l10n.py` добавить `UI_RU` (и `UI_EN` и т.д.) — словарь
   «исходная строка → перевод».
2. Заменить строки на вызов `l10n.tr("Скачать")` (простой `_()`-хелпер).
3. Для плюралов — функция `l10n.plural(n, "файл", "файла", "файлов")`.
4. Плюс: ничего не надо устанавливать, единый механизм с логом. Минус:
   вся морфология — руками, нет инструментов разметки.

### Шаги в любом случае

1. Завести `tr()`-хелпер и каталог переводов (A или B).
2. Пройтись по файлам из таблицы выше, заменить пользовательские строки
   (не трогать docstring-и, имена классов, `logger.*` — их локализует `l10n`).
3. Решить вопрос плюралов (Qt `%n` или свой `plural()`).
4. Добавить переключатель языка в `SettingsDialog` (рядом с темой), хранить
   в `config.json` (`lang`), применять на лету или при перезапуске.
5. Проверить: все окна, меню, трей, сообщения, tooltip-ы, статусы.

## Что уже можно переиспользовать

- `l10n.py` — механизм словаря + `set_language()`/`get_language()`
  + `verify()` для проверки плейсхолдеров. Для интерфейса добавится
  `UI_*`-словарь и `tr()`/`plural()`-хелперы.
- `db.get_log_language()`/`set_log_language()` — паттерн хранения языка
  в `config.json` (для интерфейса ключ можно назвать просто `lang`).
- `LOG_LOCALIZATION.md` — та же структура документации для лога.
