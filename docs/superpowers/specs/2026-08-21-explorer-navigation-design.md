# Дизайн: Навигация как в Проводнике Windows (Группа А)

**Дата:** 2026-08-21
**Версия проекта:** 0.11.10
**Задачи Плана 1.x:** 1.1 (адресная строка/breadcrumbs), 1.2 (синхронизация дерева с навигацией), 1.10 (выделение при возврате на уровень вверх)
**Статус:** согласовано с пользователем (3 части дизайна утверждены)

---

## 1. Цели и объём

Сделать навигацию по Менеджеру соответствующей привычкам Проводника Windows:

1. **1.1 Адресная строка** — кликабельные хлебные крошки под тулбаром + режим ручного ввода пути (Ctrl+L / Alt+D / клик по пустому месту).
2. **1.2 Синхронизация дерева** — при любом переходе из таблицы/крошек/ввода дерево раскрывает и выделяет текущую папку; раскрытие мгновенное, из SQLite, без ожидания API; стрелки раскрытия подпапок рисуются по данным БД.
3. **1.10 Выделение при возврате вверх** — «..», Backspace, Alt+Up выделяют в таблице папку, из которой вышли.

Вне объёма: Tab-навигация, type-ahead, F2 в дереве, inline-rename, Ctrl+Shift+N, ПКМ по пустому месту дерева, копировать как путь, свойства (группы Б и В).

### Текущее состояние (проверено по коду)

- Все переходы идут через `_navigate_to_folder()` (ui.py:3636) — единая точка интеграции.
- История Назад/Вперёд уже есть (`_nav_history`, `_nav_index`, ui.py:3605–3672) — не трогаем.
- Дерево НЕ синхронизируется с навигацией из таблицы; при «..» и Backspace есть явные `tree_view.clearSelection()` (ui.py:4551, ui.py:4585) — баг 1.2.
- `FolderTreeModel` (ui_tree_model.py): ленивая загрузка детей через `_ApiListThread`; `hasChildren()` у незагруженных узлов оптимистично `True`.
- `db.get_children(folder_path)` (db.py:832) возвращает прямых детей из SQLite.
- Существует механизм восстановления выделения `_pending_selection` → `_restore_selection()` в `_on_folder_loaded` (ui.py:462).

## 2. Адресная строка (breadcrumbs)

### Размещение и структура

- Второй `QToolBar` через `addToolBarBreak(Qt.TopToolBarArea)` — отдельная полоса под основным тулбаром, на всю ширину окна.
- Внутри тулбара контейнер `QWidget` c `QStackedLayout`, две страницы:
  - **Крошки:** `QHBoxLayout` из сегментов `[Яндекс Диск] ▸ [Папка] ▸ [Подпапка]`. Сегмент — плоская `QToolButton` (клик → переход к этому предку); разделитель — `QLabel` «▸». Последний сегмент (текущая папка) — жирный, некликабельный.
  - **Ввод:** `QLineEdit` с полным облачным путём (`/Загрузки/Отчёты`).

### Режим ввода

- Вход: Ctrl+L, Alt+D, клик по пустому месту строки крошек.
- Enter → переход через `_navigate_to_folder()`; Esc → возврат к крошкам.
- Автодополнение: `QCompleter` по списку папок из БД (`SELECT cloud_path FROM files WHERE type='dir'`), режим `InlineCompletion | PopupCompletion`. Список перечитывается в фоне при каждом входе в режим ввода (запрос дешёвый), чтобы completer не устаревал.

### Переполнение (узкое окно)

- В `resizeEvent` контейнера пересчёт видимости: если сегменты не помещаются — средние скрываются, вместо них кнопка «…» с `QMenu` (список скрытых предков).
- Первый («Яндекс Диск») и последний сегменты видны всегда.

### Обновление и ошибки

- При каждом успешном переходе строка перестраивается из `_current_path`.
- Несуществующий путь: остаёмся в режиме ввода, текст выделен; статус-бар «Папка не найдена».
- Нормализация пути: убрать хвостовые `/`, схлопнуть `//`; пустой ввод → корень `/`.

## 3. Синхронизация дерева из БД

### Трёхуровневая загрузка узла

| Состояние | Дети | Стрелка | Источник | Скорость |
|-----------|------|---------|----------|----------|
| не загружен | нет | оптимистичная `True` | — | — |
| `db_loaded` (новое) | есть, из SQLite | точная по БД | `_DbChildrenThread` | ~мс |
| `loaded` (API) | есть, сверено с облаком | точная | `_ApiListThread` | сотни мс |

- `hasChildren()`: `db_loaded` → `len(children) > 0`; `loaded` → `_has_children`; иначе `True`.
- Новые методы `FolderTreeModel`:
  - `populate_children_from_db(path, folders, with_subdirs)` — вставить детей из БД, пометить `db_loaded`, записать точные стрелки;
  - `merge_children_from_api(path, items)` — досинхронизировать `db_loaded`-узел результатом API (добавить новых, убрать удалённых, выставить `loaded=True`). Защита от повторной вставки: существующий guard `parent_item.loaded` дополняется проверкой `db_loaded`.

### Поток `_DbChildrenThread`

Новый QThread по образцу `_ApiListThread`. Один SQL-запрос достаёт сразу два уровня:

```sql
SELECT cloud_path FROM files WHERE type='dir' AND cloud_path LIKE 'parent/%'
```

Группировка по первому сегменту после `parent/` в Python: уровень 1 = прямые подпапки; наличие второго сегмента = есть ли у папки свои подпапки (для стрелок). Статусы детей — существующий `get_folder_batch_aggregate_status()`.

### Ходок `_sync_tree_to_path(path)`

Вызывается из `_navigate_to_folder()` после смены `_current_path`. Конечный автомат:

1. Разбить путь на сегменты; очередь предков: `/`, `/A`, `/A/B`, …
2. Голова очереди: узел найден в модели? Нет → DB-populate родителя через `_DbChildrenThread`, колбэк продолжает ходок.
3. Узел есть → expand; если нет `loaded` (API) — фоново запустить обычный API-refresh, ходок не ждёт.
4. Очередь пуста → `selectionModel().setCurrentIndex(цель, ClearAndSelect)` + `scrollTo(цель)`.

- **Защита от петли:** программный select триггерит `_on_tree_selection_changed` → навигацию. Флаг `_tree_sync_active`: обработчик при нём выходит; сброс после применения выделения.
- **Удаление багов 1.2:** убрать `tree_view.clearSelection()` в ui.py:4551 («..») и ui.py:4585 (Backspace).
- **Офлайн:** ходок полностью работает на БД; API-досинхронизация тихо не возвращается.
- **Частичный путь:** если целевой папки нет в БД — остановиться на глубайшем существующем предке, выделить его, предупреждение в статус-баре.

## 4. Выделение при возврате на уровень вверх (1.10)

`_navigate_to_folder(path, select_after: str | None = None)`. Точки подъёма передают путь папки, из которой уходим:

| Точка | Код |
|-------|-----|
| Строка «..» в таблице | ui.py:4550 (`is_parent_nav`) |
| Backspace в таблице | ui.py:4582 |
| Alt+Up / кнопка «Вверх» | `_nav_up()` ui.py:3630 |

Механизм: `select_after` подменяет снимок `_pending_selection`; восстановление — существующий код в `_on_folder_loaded` (ui.py:462), идемпотентно при повторной перерисовке после API. Если папку удалили — выделение не найдётся, без ошибки.

## 5. Обработка ошибок

| Ситуация | Поведение |
|----------|-----------|
| Несуществующий путь во вводе | Остаться в режиме ввода, текст выделен; статус-бар «Папка не найдена» |
| Путь частично есть в БД | Ходок до глубайшего предка + выделить его + предупреждение |
| Нет сети | Раскрытие из БД работает; API-refresh тихо не возвращается |
| HTTP 401 | Существующий `_handle_auth_error()` |

## 6. Потоки

- **Главный поток:** мутации модели (требование QAbstractItemModel), перестроение крошек, выделение.
- **`_DbChildrenThread`** (новый): только SELECT из SQLite.
- **`_ApiListThread`**: без изменений.
- Новых локов не нужно: существующие `db._lock` / `_read_conn`.

## 7. Тестирование

### Юнит-тесты (pytest, offscreen)

1. Новый метод БД (двухуровневая выборка папок) — фиксированная БД в памяти.
2. Нормализация путей (хвостовые слэши, двойные слэши, пустая строка, корень).
3. Модель: `populate_children_from_db` → точные стрелки; `merge_children_from_api` → добавление/удаление детей, переход в `loaded`.

### Ручной чек-лист

- Двойной клик по папке в таблице → дерево раскрылось и подсветило её.
- Backspace / «..» / Alt+Up → таблица выделила бывшую папку, дерево синхронизировалось.
- Ctrl+L → ввод пути → Enter → переход; Esc → возврат к крошкам.
- Узкое окно → средние сегменты сворачиваются в «…», меню открывается.
- Офлайн (без сети) → раскрытие глубокого пути из БД работает.
- Путь с 5+ уровнями, никогда не открывавшийся → всё раскрывается, стрелки корректны.
- Регресс: поиск, история Назад/Вперёд, DnD не сломаны.
